# MEXC Screener

Скринер криптопар MEXC (публичный WebSocket miniTicker-поток + подписанный REST для приватного
аккаунта) с разделом «Финрез» (аналитика баланса и сделок) и тремя эвристиками отбора монет
(Алгоритмы / Неэффективности / Пробой плотностей). Есть веб-версия (открывается прямо в браузере)
и десктоп-версия под Windows/macOS/Linux (обёртка Neutralino.js).

Раньше проект жил одним файлом (`mexc_screener.html`, ~1.5 МБ). Этот репозиторий — та же кодовая
база, но разложенная по папкам для обычной разработки (редактор/git/Claude Code), а не только через
Cowork.

## Быстрый старт: запустить прямо сейчас, без сборки

В корне репозитория уже лежит готовый `MEXC-Screener-Windows.zip` — распакуйте, запустите
`start.bat` (снимает блокировку Windows с непонятного .exe и сразу открывает программу) или сам
`MEXC-Screener.exe`. Это снимок текущего кода на момент упаковки архива — устанавливать ничего не
нужно.

Если после этого правите код и хотите видеть изменения — см. раздел "Как обновлять код и
перезапускать через .exe" ниже: там всё сводится к двойному клику на один файл.

## Как обновлять код и перезапускать через .exe

Важно понимать сразу: **Neutralino не умеет "на лету" подхватывать изменения в уже запущенном .exe**
(это проверено экспериментально) — исполняемому файлу обязательно нужен пересобранный пакет ресурсов
рядом с собой или внутри себя. Так что "изменить код → просто перезапустить старый .exe" не сработает
— .exe всегда будет показывать код на момент своей сборки.

Но пересборка здесь **не компиляция** — это просто переупаковка файлов (доли секунды — пара секунд),
и весь цикл сведён к одному действию:

1. Правите `web/index.html` / `web/css/styles.css` / `web/js/app.js`.
2. Двойной клик на `desktop/update-and-run.bat` (Windows) — или `desktop/run-dev.sh` в
   терминале на macOS/Linux.
3. Скрипт сам подхватывает свежий код из `web/`, пересобирает приложение и сразу открывает уже
   ОБНОВЛЁННОЕ окно программы.

Требуется один раз установить Node.js и Neutralino CLI (`npm install -g @neutralinojs/neu`) —
`update-and-run.bat` сам предложит это сделать при первом запуске, если чего-то не хватает.

Этот способ (`run-dev.js`) собирает быстрый, "рабочий" вариант — папка `desktop/dist/` с .exe и
рядом лежащим файлом ресурсов. Когда захотите отдать кому-то ОДИН файл `.exe` (без папки рядом) —
используйте `build.sh` ниже, он делает более медленную, но полностью портативную сборку.

## Как посмотреть/поправить веб-версию

Это статический сайт, сервер не нужен — достаточно открыть `web/index.html` в браузере (двойной
клик или `open web/index.html` / `xdg-open web/index.html`). Для разработки удобнее поднять любой
локальный статик-сервер из корня `web/`, например:

```bash
cd web && python3 -m http.server 8080
# затем открыть http://localhost:8080
```

Редактируется как обычный сайт: разметка — `web/index.html`, стили — `web/css/styles.css`, вся
логика — `web/js/app.js` (один большой файл, обёрнутый в `(function () { 'use strict'; ... })()`,
никаких модулей/сборщика — открывается и редактируется напрямую).

Подключение по API-ключу MEXC работает только в desktop-версии (у биржи нет permissive CORS для
браузера ни на публичные, ни на приватные эндпоинты — см. `docs/00-notes.md`). В браузере доступен
весь функционал скринера и графиков, но не приватный кабинет/Финрез.

## Как собрать финальный портативный .exe для раздачи (Windows/macOS/Linux)

Нужны Node.js + npm и Neutralino CLI:

```bash
npm install -g @neutralinojs/neu
cd desktop
./build.sh            # собрать .exe/.app/бинарники + упаковать MEXC-Screener-Windows.zip
./build.sh --embed    # то же самое, и дополнительно зашить получившийся zip обратно в web/index.html
                       # (тогда кнопка «Скачать приложение» в самом скринере работает офлайн, без стороннего хостинга)
```

Если `neu` не установлен глобально — можно временно подменить: `NEU="npx @neutralinojs/neu" ./build.sh`.

Скрипт делает всё то же самое, что раньше делалось вручную по шагам между раундами разработки:
копирует `web/` в `desktop/resources/`, добавляет один-единственный desktop-специфичный тег
(`<script src="/js/neutralino.js">` сразу после `<title>` — без него нативный мост Neutralino не
инициализируется, см. `docs/04-round4.md`), запускает `neu build --release --embed-resources`,
собирает `MEXC-Screener.exe` + `README.txt` + `start.bat` (снимает Windows Mark-of-the-Web) в
`MEXC-Screener-Windows.zip`. Результат — `MEXC-Screener-Windows.zip` в корне репозитория и
собранные бинарники в `desktop/dist/` (не коммитить — это build output).

Логика приложения (`web/js/app.js`) не требует отдельной desktop-сборки кода — она уже написана как
progressive enhancement: если `window.Neutralino` есть, используется нативный мост (`nlCall`,
`nativeCurlGet` — обход CORS через `curl.exe`), если нет — обычный браузерный `fetch()`.

## Известные архитектурные ограничения (коротко, подробности в docs/)

- MEXC разрешает не больше ~30 потоков на одно WebSocket-соединение → скринер использует
  агрегированный публичный miniTicker-поток по всему рынку, а не подписку на стакан (`depth`) по
  каждой паре — поэтому нет настоящего order-book-based анализа плотностей/спуфинга, только тиковая
  аппроксимация.
- MEXC не отдаёт единый список сделок по всем парам сразу, только `/api/v3/myTrades?symbol=X` — для
  Финреза приходится заранее знать список символов (решено через `knownSymbols` — монета, увиденная
  в балансе хоть раз, запоминается навсегда, см. `docs/11-round11.md`).
- MEXC блокирует встраивание своей страницы биржи в iframe (проверено эмпирически в раунде 14) —
  график всегда рисуется своим canvas-движком по данным REST `/api/v3/klines`, а "посмотреть точно
  такой же график, как на самой бирже" — только через кнопку "Открыть на бирже" (внешняя вкладка).
