# MEXC Screener — «свой график» на уровне TradingView (раунд 5)

Продолжение `04-round4.md`. Запрос: "нужно его доработать и сделать функционал
и дизайн на высшем уровне, примерно как трейдинг вью" — про запасной канделстик-график (`#ownChartContainer`
/ `drawCandleChart`), который уже умел зум/пан/уровни/трендлинии/линейку (раунд 4, п.6).

## Что добавлено

- **Панель объёма** — отдельная зона снизу внутри того же canvas (не отдельный элемент): `plotHTotal`
  делится на `plotH` (цена, ~84%) и `volumeH` (объём, ~16%) с зазором `paneGap=6`. Столбики объёма
  цветные по направлению свечи, полупрозрачные (`rgba(38,166,154,.45)`/`rgba(239,83,80,.45)`).
- **Переключатель типа графика**: Свечи / Линия / Область (`ownChartType`, кнопки `data-charttype` в
  тулбаре). Линия/область — сглаженный путь через закрытия (`quadraticCurveTo`, та же техника, что в
  `drawPnlChart`), область — заливка линейным градиентом сверху вниз.
- **MA(7)/MA(25)** — переключаемые скользящие средние (`ownChartShowMA`, кнопка `#ochartMaToggle`,
  иконка пульса). `ochartSMA(candles, period)` считает SMA по **всему** массиву свечей (не по видимому
  срезу), иначе на левом краю окна значений бы не было. Цвета: MA7 амбер `#FFB800`, MA25 синий `#1E80FF`
  (переиспользует акцентный синий, уже принятый в приложении).
- **Вотермарк тикера** — `#ochartWatermark`, полупрозрачный крупный текст по центру canvas-обёртки,
  за canvas (canvas прозрачный — только `clearRect`, а не заливка фоном — фон даёт родительский
  `.own-chart-container`). Текст выставляется в `loadOwnChart()` при каждой загрузке.
- **Бейдж последней цены** — закрашенный прямоугольник с ценой на правой оси в цвет направления
  последней свечи (только когда `offset===0`, т.е. видна самая свежая свеча), как в реальных терминалах.
- **Легенда OHLC+Vol+%** в левом верхнем углу — показывается ВСЕГДА (не только при наведении):
  по умолчанию последняя свеча в видимом окне, при наведении курсора — наведённая свеча.
- **Кнопка "К живым данным"** (`#ochartLiveBtn`) — всплывает (класс `.show`) когда `ownChartView.offset>0`
  (пользователь панорамировал в историю), по клику сбрасывает `offset` в 0.
- **Вертикальные линии сетки** добавлены к уже существовавшим горизонтальным (были только гориз. линии) —
  на всю высоту обеих панелей (цена+объём), на тех же x, что и подписи времени снизу.
- **Цветовая палитра** переведена на классические TradingView-цвета: `#26A69A` (рост) / `#EF5350`
  (падение) вместо прежних `#00C076`/`#F84960`.
- **Сброс масштаба при смене ТФ**: добавлен `ownChartLoadedTF` — раньше `ownChartView` (зум/пан)
  сбрасывался только при смене монеты; теперь ещё и при смене таймфрейма (окно, подобранное для 5м,
  бессмысленно после переключения на 1д). Построения (`ownChartDrawings`) по-прежнему привязаны только
  к символу, не к ТФ — переживают переключение таймфрейма.
- Crosshair переработан под две панели: горизонтальная линия+подпись цены — только когда курсор в
  ценовой панели; вертикальная линия — на всю высоту (цена+объём), как в TradingView.

## Технические детали / грабли

- Canvas у "своего графика" теперь **прозрачный фон** (раньше тоже не заливался явно, просто не было
  вотермарка позади, поэтому это не было заметно) — фон `#131722` даёт родительский
  `.own-chart-container`, вотермарк-div лежит между ним и canvas по z-index.
- `wireOwnChartInteractions` — граница хит-тестинга мыши (`mousemove`) была `chart.plotH + padTop +
  padBottom` (весь плот = только бывшая единая ценовая панель); после разделения на панели это стало
  неверным (обрезало бы объём/время), заменено на `chart.volTop + chart.volumeH + chart.padBottom`.
- Порядок отрисовки слоёв (снизу вверх): сетка → объём → цена (свечи/линия/область) → MA →
  бейдж последней цены → построения пользователя → превью трендлинии → линейка → crosshair → легенда.

## Повторно наступленные грабли сборки (снова!) — теперь задокументировано в двух местах

При пересборке .exe этого раунда скрипт регенерации `resources/index.html` из `mexc_screener.html`
СНОВА нужно было не забыть тег `<script src="/js/neutralino.js"></script>` (см. `04-round4.md`,
раздел "КРИТИЧЕСКИЙ баг сборки") — на этот раз он был добавлен сразу, в тот же питон-скрипт, который
делает копию+вырезание download-app/desktopAppData+вставку `Neutralino.init()`. После сборки строка
подтверждена в скомпилированном .exe через `strings`, SHA256 embedded-zip внутри `mexc_screener.html`
сверен со standalone zip — совпадает.

**На будущее**: этот питон-скрипт регенерации (копия mexc_screener.html → вырезать download-app+
desktopAppData → вставить Neutralino.init() → вставить `<script src="/js/neutralino.js">`) стоит
сохранить как эталон и переиспользовать/сверять на каждую последующую пересборку, а не переписывать
с нуля по памяти — именно потеряный на лету шаг стал причиной бага прошлого раунда.
