# MEXC Screener — трейды, лучи/прямые, дашборд баланса, полировка UI (раунд 6)

Продолжение `05-round5.md`. Запрос от юзера (по 3 скриншотам — свой график, дашборд баланса, главная
таблица): "дизайн и функционал суроват... нужно довести всё до идеала, аналог TradingView по
функционалу... добавить лучи/прямые/наклонные линии... справа лента сделок MEXC вечно грузится...
баланс — сделать нормальный подробный дашборд с анимациями и статистикой... на главной — доработать
интерфейс, красивые анимации в меру, подсветка в нужных местах".

Разбито на 5 подзадач, все выполнены в этом раунде.

## 1. Лента "Последние сделки" — чинили бесконечную загрузку

**Расследование (важно для будущего)**: проверили две гипотезы через официальный репозиторий
`github.com/mexcdevelop/websocket-proto` — (а) устаревший номер поля `publicDeals` в proto-схеме,
(б) устаревшее имя канала `spot@public.deals.v3.api.pb@<symbol>`. **Обе не подтвердились** — актуальны
и поле `301`, и формат имени канала (сверено построчно с официальными `.proto`). Реальная причина —
не в протоколе, а в UX: панель ждала только WS-сообщения (на неликвидных парах может пройти минуты
до первой сделки), а `dealsWs.onmessage` молча проглатывал текстовые фреймы (в т.ч. возможные
ack-ошибки подписки), из-за чего сбой было не отличить от "просто тихо".

**Фикс**:
- `fetchRecentTrades(raw, limit)` — REST `/api/v3/trades` (сразу отдаёт последние N сделок, без
  ожидания WS), с тем же fallback-паттерном browser fetch → `nativeCurlGet` через curl.exe, что и у
  `fetchKlines`/`mexcSignedRequest`. `isBuyerMaker` инвертируется в `buy` (тейкер-покупатель).
- `createTradeRow(price, qty, buy, timeMs, animate)` — вынесенный хелпер рендера строки сделки
  (раньше HTML дублировался инлайн).
- `loadTrades(raw)` — сразу сеет историю через REST, затем подписывается на WS; если через 20с нет
  ни одной сделки — честное сообщение "тихая пара", а не вечный спиннер.
- `subscribeDeals(raw)` — текстовые фреймы теперь парсятся, `console.warn` при `code !== 0` (ack-ошибка
  подписки больше не проглатывается молча).

## 2. Лучи и прямые линии на "своём графике"

Добавлены к существовавшим отрезку (trend) и уровню (hline): **луч** (`ray`, бесконечен в одну
сторону) и **прямая** (`xline`, в обе стороны). Реализовано через Liang-Barsky клиппинг:

- `clipRayToRect(x1,y1,dx,dy,xmin,xmax,ymin,ymax,tLo,tHi)` — новый хелпер рядом с `distToSegment`,
  обрезает бесконечную/полубесконечную линию (точка + вектор направления) по прямоугольнику ценовой
  панели. `trend` — `tLo=0,tHi=1`; `ray` — `tLo=0,tHi=Infinity`; `xline` — `tLo=-Infinity,tHi=Infinity`.
- `distToSegment` обобщён — принимает опциональные `tLo/tHi` (по умолчанию 0/1, обратная
  совместимость), используется и для правого клика (удаление) на лучах/прямых.
- Разметка/удаление используют общий поток: `ownChartPendingTrend = {tool, p1}` → второй клик →
  `ownChartDrawings.push({type, p1, p2})`; маркеры-точки рисуются в исходных `p1/p2`, а линия тянется
  до края панели через `clipRayToRect`.
- Кнопки в тулбаре: `data-tool="ray"` (иконка `ri-arrow-right-up-line`), `data-tool="xline"`
  (`ri-expand-diagonal-line`), плюс подсказки в `updateOchartHint()`.

## 3. Дашборд баланса — подробная статистика + анимации

- **Сетка из 4 плиток** (`buildBalanceStatsGridHtml`, класс `.balance-stats-grid`) над списком
  периодов: изменение портфеля за 24Ч/7Д/30Д (`computeBalanceDelta(hist, total, 'day'|'week'|'month')`
  — независимо от выбранной пилюли периода ниже) + 4-я плитка "Активы" (кол-во ценообразованных +
  сколько "пыли" скрыто). Цвет/иконка по знаку (`up`/`down`/`flat`), 4-я плитка — нейтральный синий
  акцент (`.stat-tile.neutral`).
- **Count-up анимация hero-суммы**: `animateNumberText(el, from, to, duration, formatFn)` — плавно
  "прокручивает" текст от старого к новому значению (ease-out cubic, 500мс) + короткий пульс свечения
  (`.balance-hero-value.pulse`, keyframe `heroValuePulse`). Срабатывает **только** если сумма реально
  изменилась между авто-обновлениями (раз в 3с) — иначе бы мигало на каждый тик впустую.
- **Anti-flicker для авто-обновления**: `renderAccountBalances()` определяет `isRefresh` (уже была ли
  отрисована `.balance-hero` в DOM) — на первом показе страницы плитки/строки активов проигрывают
  анимацию появления (`statTileIn`/`balanceRowIn`, стаггер через `nth-child`/`--row-i`), на всех
  последующих refresh (каждые 3с) анимация подавлена классом `.no-anim`, чтобы дашборд не "мигал"
  каждые 3 секунды.
- Hover-свечение на карточке доната и строках активов (`.balance-donut-card:hover`,
  `.balance-asset-row:hover`), в том же визуальном языке (`box-shadow`/`border-color` на акцентных
  CSS-переменных), что уже был в `.balance-hero`.

## 4. Полировка главной таблицы — анимации и подсветка "в меру"

Ключевое ограничение: `renderTable()` перерисовывает **весь** `tbody.innerHTML` на каждый вызов, а
вызывается она часто (фильтры вживую, аналитика раз в `updateIntervalMs`, по умолчанию 10с). Поэтому
анимация появления **всей** таблицы на каждый рендер была бы навязчивым миганием — сделано иначе:

- **Тикер-флеш цены**: `prevRowSnapshot` (Map symbol → {price, change24}) хранит значения с прошлого
  рендера; если цена монеты реально изменилась — ячейка `.cell-price` получает `.cell-flash-up`/
  `.cell-flash-down` (короткая заливка зелёным/красным, keyframes `cellFlashUp`/`cellFlashDown`, 0.8с)
  — как живая лента цен на бирже/TradingView. Не изменившиеся ячейки анимацию не получают.
- **Анимация появления строк** — только на первой заливке таблицы (`isFirstFill`, когда `tbody` был
  пуст или показывал `.empty-state`), класс `.row-enter` со стаггером по `animation-delay` (макс. 24
  первых строк). На живых обновлениях (фильтры/аналитика) — не переигрывается.
- **Выделенная строка** (`tr.selected`) — синий акцентный `box-shadow: inset 3px 0 0 var(--blue)`
  вместо нейтрального фона.
- **Свечение сигнальных бейджей**: `.signal-buy`/`.signal-sell`/`.signal-strategy` получили
  `box-shadow` в цвет сигнала; точки-индикаторы (`.dot-buy`/`.dot-sell`) — пульсирующее свечение
  (переиспользован существующий keyframe `pulse`, уже использовавшийся в `.status-dot`).
- **Метрики топбара** (Показано/Пары): `setMetricValue(id, value)` — пульс свечения
  (`.metric-value.metric-pulse`, keyframe `metricPulse`) только при реальном изменении числа, через
  `prevMetricValues`. `metricTrades` (обновляется на каждую сделку из WS, слишком часто) сознательно
  НЕ подключён к пульсу — иначе мигало бы непрерывно.
- **Активный пункт меню слева** — акцент переведён с белого на синий (`var(--blue)`), добавлено
  свечение на полоске-индикаторе слева, лёгкий `translateX` на hover.

## 5. Пересборка .exe (историческая версия пайплайна — заменена в раунде 14)

Полный цикл был реализован тогда как инлайновая последовательность bash/python-команд без сохранения
скрипта на диск между раундами (что позже стало проблемой — см. `docs/14-round14.md`). Ключевые шаги:
копия `mexc_screener.html` → `resources/index.html` → вырезание `download-app` nav-пункта и
`<script type="text/plain" id="desktopAppData">` → вставка `<script src="/js/neutralino.js"></script>`
сразу после `<title>` → вставка `if (window.Neutralino && typeof Neutralino.init === 'function') {
Neutralino.init(); }` внутри обработчика клика `resetFilters` → `node --check` → `neu build --release
--embed-resources` → упаковка `MEXC-Screener.exe` + `Запустить.bat` + `README.txt` в
`MEXC-Screener-Windows.zip` → base64 обратно в `desktopAppData` → SHA256 сверка.

> **Актуальный, поддерживаемый пайплайн** — `desktop/build.sh` в этом репозитории (раунд 14):
> исходники честно разбиты на `web/index.html` + `web/css/styles.css` + `web/js/app.js`, а сборка
> desktop-версии — воспроизводимый скрипт, а не инлайновые команды по памяти.
