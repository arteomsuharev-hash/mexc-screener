# MEXC Screener — заметки по проекту

## Открытая задача: подключение по API-ключу в веб-версии (сайт)

Десктоп-приложение подключается по API-ключу нормально. Веб-версия (просто сайт в браузере) — НЕТ:
MEXC не разрешает браузеру напрямую слать подписанные запросы к приватному REST API (CORS-политика
на стороне биржи), обойти это в статичном HTML без сервера-посредника невозможно.

Согласованное решение (озвучено пользователю, ждём подтверждения): небольшая локальная
программа-прокси, которую пользователь один раз скачивает и запускает рядом с браузером. Пока не
реализовано — вернуться к этому, когда пользователь подтвердит.

## Решённые проблемы с подключением по API (desktop, Neutralino)

1. **Native-мост завис намертво** — баг тайминга самой библиотеки neutralino.js: она открывает
   единственный WebSocket к native-серверу ОДИН раз при `Neutralino.init()`, без переподключения при
   неудаче первой попытки. Исправлено: свой WebSocket-мост `nlBridgeConnect()`/`nlCall()` в
   mexc_screener.html, используется вместо `Neutralino.os.execCommand`/`Neutralino.app.getConfig`
   везде в приложении.
2. **"Timestamp for this request is outside of the recvWindow"** — подпись/timestamp считались один
   раз до попытки через браузер; пока fetch() ждал таймаута/CORS-отказа (до 8с), время утекало, и
   когда запрос уходил через curl.exe — подпись уже была просрочена. Исправлено: `buildSignedUrl()`
   пересобирает timestamp+подпись заново перед native-попыткой; recvWindow увеличен с 5000 до 10000мс
   про запас. При этой ошибке приложение теперь также подсказывает проверить системные часы.
3. **Статус "Ошибка" зависал навсегда** после единичного сетевого сбоя — успешный опрос не сбрасывал
   статус обратно. Исправлено: статус возвращается в "Подключено" при первом же успешном ответе;
   в "Ошибку" уходит только после 3 неудач подряд (не с первого сбоя).
4. Баланс обновляется раз в 3с отдельным таймером (`startBalanceAutoRefresh`/`stopBalanceAutoRefresh`),
   пока открыта страница аккаунта — независимо от общего интервала "Автообновление" в настройках.

## Пайплайн пересборки desktop-приложения (Neutralino, Windows .exe)

См. `desktop/build.sh` в этом репозитории — актуальный, проверенный и рабочий скрипт сборки
(реконструирован в раунде 14 после того, как предыдущий инлайновый пайплайн потерялся между
раундами). Ключевой момент, из-за которого раньше не раз ломалась сборка: тег
`<script src="/js/neutralino.js"></script>` должен стоять сразу после `<title>` — нативный сервер
Neutralino ищет этот якорь регэкспом в HTML и только рядом с ним инжектит
`window.NL_PORT`/`window.NL_TOKEN`/`window.Neutralino`. Без тега — не появляется ничего из этого,
и весь desktop-only функционал (свой мост `nlCall`, `nativeCurlGet` и т.д.) молча не работает, как
будто это веб-версия.

## Стратегии профилей (Алгоритмы / Неэффективности / Пробой плотностей)

Основаны на исследовании по микроструктуре рынка (равномерность оборота как признак бота,
дивергенция цены/объёма как признак неэффективности, модель "консолидация → всплеск" для пробоя
плотности из теории объёмного профиля). Метрики в `metricsFromSnaps()`: `vol30`/`vol60` (объём за
30с/60с, не только за 5с), `rateCV` (коэффициент вариации скорости оборота между окнами 5с/30с/60с —
низкий = равномерный/ботоподобный темп), `preMove` и `zoneLow`/`zoneHigh` (движение и ценовые границы
ДО текущего всплеска — для отличения "чистого" пробоя от монеты, которая и так была волатильна).
`computeStrategyStats()` считает персентиль `steadyCV`.

**Важное архитектурное ограничение**: скринер построен на публичном miniTicker-потоке (агрегированные
тикеры по всему рынку разом), а НЕ на подписке на глубину стакана (`depth`) по каждой паре — MEXC
позволяет не более ~30 потоков на одно WebSocket-соединение, а торгуемых пар — тысячи. Настоящий
order-book-based lifecycle плотностей (DENSITY_DETECTED→STABLE→ATTACKED→CONSUMING→CONSUMED→BREAKOUT),
классификация спуфинга и т.п. физически недостижимы при таком лимите без подписки на стакан по
каждой паре — не реализованы сознательно, не по недосмотру (см. `docs/13-round13.md`).

## Баланс: "мелкие остатки" (dust) скрываются по умолчанию

Общая стоимость портфеля в скринере могла отличаться от того, что видно на самой бирже, из-за
мелких остатков дешевле $1 (MEXC, как и большинство бирж, по умолчанию прячет такие активы в своём
интерфейсе). Исправлено в `renderAccountBalances()`: `DUST_USD_THRESHOLD = 1`, активы дешевле $1 по
умолчанию скрыты из общей суммы/доната/списка (`hideDustBalances`, localStorage `mexc_hide_dust`,
дефолт — скрыто). Кнопка "Показать мелкие остатки" под списком показывает их без нового запроса к
бирже.

## Кнопка "Открыть в терминале" / интеграция с Vataga.Terminal (открытый вопрос)

Пользователь торгует через сторонний скальпинг-терминал **Vataga.terminal** (vataga.trading) и хотел
бы, чтобы клик по монете в скринере сразу открывал её в терминале (как это делают партнёрские
интеграции вроде CryptoScreener.app — правый клик по окну терминала → "Привязка к окну — Скринер",
затем скринер шлёт монету через какой-то локальный канал связи).

Публичного описания протокола/порта этой интеграции найти не удалось — ни в вики Vataga, ни в
открытом коде партнёров. Угадывать вслепую не стали (можно сделать кнопку, которая либо ничего не
делает, либо шлёт данные в никуда). Текущий рабочий компромисс: кнопка `#copyForVatagaBtn` (📋) рядом
с "Открыть на бирже" копирует тикер монеты (`BTCUSDT`) в буфер обмена — вставить в поиск Vataga можно
одним Ctrl+V.

**Следующий шаг, если пользователь захочет довести до автоклика**: написать в поддержку Vataga
(support@vataga.trading) или CryptoScreener (t.me/cryptoscreener_support) с прямым вопросом про
API/протокол для стороннего скринера — у них уже есть 6+ партнёрских интеграций, скорее всего есть
внутренний тех-документ, который просто не публикуют в открытом доступе.
