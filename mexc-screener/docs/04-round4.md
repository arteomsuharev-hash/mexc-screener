# MEXC Screener — раунд правок: сортировка стратегий, свой график, адаптивность, PnL, панель сделок

Продолжение `00-notes.md`. В этом раунде закрыты 5 запросов одним заходом.

## 1. Баг: сортировка по столбцу не работала внутри выбранной стратегии

Причина: `applySortOnly()` при активной стратегии (`activeStrategy` + `STRATEGY_DEFS[activeStrategy]`)
безусловно пересортировывала `allCoins` по `score()` и выходила — клик по заголовку столбца обновлял
`sortField`/`sortAsc` и визуальную стрелку, но реальный порядок массива тут же перезаписывался обратно.

Исправлено: добавлен флаг `strategyManualSort` (глобальная переменная, объявлена рядом с
`activeStrategy`). `sortCoins(field)` ставит его в `true`, если в этот момент активна стратегия.
`applySortOnly()` теперь всегда считает `c.__score` (нужен и для бейджа в таблице), но сортирует по
score только если `!strategyManualSort` — иначе падает в обычную сортировку по `sortField`/`sortAsc`
(с маппингом столбца "Сигнал" → `c.__score`, раз в стратегии нет обычного поля signal). `applyProfile()`
сбрасывает `strategyManualSort = false` при выборе новой стратегии — то есть каждый раз стратегия
по умолчанию открывается в рекомендованном порядке (по score), а клик по любому столбцу переключает
на этот столбец, не теряя фильтр стратегии (`match()` в `getFilteredCoins()` не трогали).

## 2. "Свой график" — резервный канделстик для пар без TradingView

TradingView не индексирует часть пар MEXC; раньше единственным запасным вариантом была ссылка на
mexc.com. Детектировать программно, что TradingView не отрисовал график, нельзя (кросс-доменный
iframe) — поэтому сделали ручной переключатель, а не автоопределение.

- Кнопка `#toggleOwnChartBtn` ("Свой график" / "TradingView") рядом с "Открыть в терминале" и кнопкой
  Vataga — показывается/скрывается вместе с ними в `loadTradingView()`.
- `#ownChartContainer` — новый слой внутри `.chart-container`, поверх `#tv_chart_container`
  (переключаются через `display:none`/`flex`, `toggleOwnChart()`).
- Данные: `fetchKlines(raw, tf, limit)` → публичный REST `GET {MEXC_REST}/api/v3/klines?symbol=...&interval=...&limit=...`
  (без подписи, ключ не нужен). `mexcKlineInterval(tf)` мапит наши ТФ-коды (1/5/15/30/60/240/D) в
  формат MEXC (1m/5m/15m/30m/60m/4h/1d).
- Рендер: `drawCandleChart(canvas, candles)` — тело+фитиль свечи, сетка с подписями цены справа,
  пунктирная линия последней цены.
- Автообновление раз в 15с, пока режим включён (`startOwnChartAutoRefresh`/`stopOwnChartAutoRefresh`),
  плюс перерисовка при смене монеты/ТФ и при ресайзе окна.

> **Обновление раунда 14**: эта кнопка и ручной переключатель полностью удалены — "свой график" стал
> единственным (и постоянным) режимом графика. Подробности — `docs/14-round14.md`.

### Фикс после первого теста: "Не удалось загрузить данные MEXC: Failed to fetch"

Браузерный fetch() к `api.mexc.com/api/v3/klines` падал с "Failed to fetch" — тот же класс проблемы,
что уже решали для приватных подписанных запросов аккаунта (`mexcSignedRequest`): у api.mexc.com нет
permissive CORS для сторонних источников ни для публичных, ни для приватных эндпоинтов. Исправлено
по тому же паттерну:
- `nativeCurlGet(url, apiKey)` — параметр `apiKey` сделан опциональным; если не передан — не добавляет
  заголовок `X-MEXC-APIKEY`, теперь годится и для публичных запросов.
- `fetchKlines()` сначала пробует browser fetch(), при ошибке в desktop-приложении (`window.Neutralino`)
  пробует `nativeCurlGet(url, null)` (curl.exe в обход CORS, как для баланса).

**Подтверждено пользователем**: после фикса свой график успешно отрисовал реальные свечи (OORT/USDT) —
цена, сетка, кнопка переключения на TradingView видны на скриншоте.

## 3. Адаптивность под размер окна

- `.bottom-panel { height: clamp(230px, 34vh, 400px); }` — тянется с высотой окна в разумных пределах.
- Промежуточные брейкпоинты: 1500px/1300px/1100px/860px для `.right-panel`/`.coin-info`/`.bottom-panel`.
- Гейдж (SVG) и донат-график баланса переведены на `aspect-ratio` + `clientWidth`-based canvas-размер
  вместо фиксированных HTML-атрибутов `width`/`height`.
- Общий debounced `window.addEventListener('resize', ...)` (180мс) перерисовывает PnL+донат и свой
  канделстик-график из закэшированных данных, без повторного похода в сеть.

## 4. "Профессиональный" PnL-график

`drawPnlChart()` дополнен: отступ+сетка+подписи цены справа, сглаженная линия через `quadraticCurveTo`,
двойное кольцо на последней точке, наведение мышью (`wirePnlChartCrosshair()`) с тултипом значения и
времени снимка (`#balancePnlTip`).

## 5. Панель "Последние сделки" + гейдж активности — визуальное обновление

- Строки сделок: цветная левая полоса-акцент (зелёная/красная, лёгкое свечение) по стороне сделки,
  fade-in анимация `.flash-in` при появлении новой строки.
- Плейсхолдер "Ожидание сделок..." → `.trades-empty`, явно удаляется при первой пришедшей сделке.
- **Попутно найденный и исправленный баг устойчивости**: у `dealsWs` не было ни `onerror`, ни `onclose` —
  при тихом разрыве лента сделок замирала навсегда. Добавлены оба обработчика, `onclose` пробует
  переподключиться через 3с, если всё ещё выбрана та же монета.
- Гейдж активности: свечение по дуге, привязанное к цвету статуса через `gaugeFill.style.color`; то же
  значение управляет ambient-свечением всего виджета через CSS-переменную `--gauge-glow`.
- Кнопка "Добавить в избранное": класс `.is-fav` — золотистая рамка/цвет/свечение, когда монета уже в
  избранном.

## 6. "Свой график" — зум/пан, инструменты рисования, линейка, редизайн

Запрос: "нужно добавить возможность прокручивать и сжимать свой график, добавить возможность выставлять
уровни, и линии, добавить линейку и улучшить его дизайн".

- **Разметка**: `#ownChartContainer` теперь `display:flex;flex-direction:column` — верхний ряд
  `.own-chart-toolbar` (инструменты) + `.own-chart-canvas-wrap` (canvas + empty-state). Старый отдельный
  DOM-тултип `#ownChartTip` убран — его функцию теперь выполняет crosshair, отрисованный прямо на canvas.
- **Тулбар** (`.ochart-tool`, `data-tool`): курсор/панорама, уровень (`hline`), трендлиния (`trend`),
  линейка (`ruler`), плюс кнопки "очистить всё" (`#ochartClear`) и "сбросить масштаб" (`#ochartResetView`).
  Активный инструмент подсвечивается (`.active`), текстовая подсказка `#ochartHint` меняется по инструменту.
- **Зум/пан**: `ownChartView = { offset, visibleCount }` — видимое окно свечей внутри полного массива
  `ownChartCandles` (фетчится с `limit: 300` вместо 200, чтобы был запас для скролла назад). Колесо мыши
  зумит к позиции курсора (пересчитывает `offset`/`visibleCount` так, чтобы время под курсором осталось
  на месте); зажать левую кнопку при инструменте "курсор" — панорама (`ownChartPanDrag`).
- **Построения**: `ownChartDrawings` — массив `{type:'hline', v}` (уровень по цене) и
  `{type:'trend', p1:{t,v}, p2:{t,v}}` (трендлиния по **абсолютным** меткам времени, не индексам свечей —
  важно, т.к. окно свечей сдвигается при каждой перезагрузке/автообновлении). Хранится в `localStorage`
  под ключом `mexc_chart_drawings`, per-symbol (`loadOwnChartDrawings`/`saveOwnChartDrawings`, raw-символ
  как ключ). Загружаются/сбрасываются **только при смене монеты** (`ownChartLoadedRaw`), не на каждый
  15-секундный автообновляющий тик — иначе зум/пан/рисунки сбрасывались бы у пользователя во время
  просмотра. Правый клик по линии/уровню — удаление (`distToSegment` для трендлиний, расстояние по Y для
  уровней, порог 8px).
- **Линейка**: зажать и тащить любым инструментом "ruler" — на graph рисуется линия + плавающий лейбл
  с Δцена / Δ% / Δбар (число интервалов таймфрейма между точками), исчезает по отпусканию кнопки мыши.
- **Crosshair**: полностью на canvas (заменил старый DOM-тултип) — пунктирные линии по X/Y, подпись цены
  на правой оси, подпись времени на нижней оси, мини-бокс OHLC наведённой свечи в левом верхнем углу.
- Всё вместе переписано в `drawCandleChart(canvas, candles)` (рендер всех слоёв по текущему состоянию) +
  новая `wireOwnChartInteractions(canvas)` (заменила `wireCandleChartCrosshair`) — обработчики wheel/
  mousedown/mousemove(window)/mouseup(window)/mouseleave/contextmenu, идемпотентно вешаются один раз на
  canvas через `canvas.__ownWired`.

### КРИТИЧЕСКИЙ баг сборки, обнаруженный сразу после этого раунда (и фикс)

При пересборке .exe в этом раунде регенерация `resources/index.html` из `mexc_screener.html` была
впервые сделана программно (python-скрипт: копия + вырезать `desktopAppData`/download-app +
вставить `Neutralino.init()`), а не вручную, как в предыдущих раундах. Скрипт упустил один момент,
которого не было видно в веб-версии по определению: **тег `<script src="/js/neutralino.js"></script>`**
в `<head>`. Он был в предыдущих (рабочих) сборках resources/index.html, но не переносился автоматически,
т.к. mexc_screener.html (веб-версия) этот тег никогда не содержит.

Симптом у пользователя: desktop .exe открывается нормально (это настоящее нативное окно Neutralino,
не браузер), таблица монет и WebSocket-лента работают, но ЛЮБОЙ desktop-only функционал (подключение
API-ключа, "свой график" при недоступности TradingView и т.д.) падает с "Failed to fetch", как будто
это веб-версия. Диагностика ("Проверить подключение") показала: `window.Neutralino: НЕТ`,
`NL_PORT: не задан`, `NL_TOKEN: НЕ задан`.

Причина найдена через анализ бинарника Neutralino (`strings` по `bin/neutralino-linux_x64`): нативный
сервер приложения ищет в отдаваемом HTML якорь по regex `.*neutralino.js$` и **только рядом с этим
якорем** вставляет `<script>var NL_PORT=...;var NL_TOKEN='...';...</script>`. Без самого тега — некуда
инжектить, поэтому не появляются ни `window.Neutralino`, ни `NL_PORT`/`NL_TOKEN`. Свой мост
`nlBridgeConnect()`/`nlCall()` не зависит от `Neutralino.init()`, но напрямую читает
`window.NL_PORT`/`window.NL_TOKEN` — соответственно тоже не работал.

Фикс: тег добавлен в `<head>` сразу после `<title>`. **Важно на будущее**: при любой последующей
регенерации `resources/index.html` обязательно проверять/переносить этот тег — он не появится сам,
раз в исходном веб-файле его нет. Этот урок закреплён в `desktop/build.sh` этого репозитория.
