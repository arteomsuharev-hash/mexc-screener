# MEXC Screener — реальный список монет в журнале сделок (раунд 11)

Продолжение `10-round10.md`. После редизайна юзер написал: «так надо сделать список монет реальным и
рабочим, и по нажатию на монету что бы открывался график с точкой входа и точкой выхода».

## Диагноз

Список монет на вкладке «Сделки» (чипы + новая таблица из раунда 10) строился ТОЛЬКО из
`lastBalanceState.priced` — то есть только из монет, которые СЕЙЧАС есть в балансе. Как только
позиция полностью закрывалась (продана в ноль), монета тут же выпадала из списка — а вместе с ней
и её реализованный PnL пропадал из ВСЕЙ статистики Финреза (Обзор/P&L/Риски), не только из журнала.
Причина архитектурная: MEXC не отдаёт единый список сделок по всем парам сразу, только
`/api/v3/myTrades?symbol=X` — нужно заранее знать, по каким символам вообще спрашивать, а знали
только про текущий баланс. Это и есть «нереальный список», о котором написал юзер.

## Исправление

**1. Постоянная память символов (`knownSymbols`, localStorage `mexc_known_trade_symbols`)** — каждый
символ, который хоть раз видели в балансе за время работы приложения, запоминается НАВСЕГДА (не
только на сессию). Хук добавлен в `renderAccountBalances`: сразу после вычисления `pricedAll`,
до фильтра пыли, для каждой монеты с известной парой вызывается `rememberSymbol(asset, raw)`.
Так однажды проданная в ноль позиция остаётся в статистике даже после полного закрытия — если
приложение хоть раз видело её в балансе.

**2. `finresLoadRealized()` берёт объединение** текущего баланса и `knownSymbols`, а не только баланс:
```js
const targetMap = {};
priced.forEach(r => { const c = coinMap.get(r.asset+'/USDT'); if (c && c.raw) targetMap[r.asset] = c.raw; });
Object.keys(knownSymbols).forEach(asset => { targetMap[asset] = knownSymbols[asset]; });
```
Это единственная точка, откуда весь Финрез (Обзор/P&L/Риски/Сделки) берёт список символов — правка
в одном месте чинит статистику сразу везде, не только в журнале.

**3. Поиск по ВСЕМ парам MEXC** — на вкладке «Сделки» над чипами (которые остались быстрым доступом
к текущему балансу, подписаны «Из текущего баланса») добавлено поле поиска
(`#finresCoinSearchInput` + выпадающий список `buildCoinSearchResultsHtml`), которое ищет по ВСЕМ
`.../USDT`-парам в `coinMap` (полный рынок MEXC, известный скринеру через WS-поток тикеров), а не
только по балансу. Совпадения, начинающиеся с запроса, ранжируются выше подстрочных; уже добавленные
в журнал монеты помечены зелёной галочкой «в журнале». Выбор монеты: `rememberSymbol()` (попадает во
всю статистику навсегда) → сразу открывает `openJournalForAsset()` (график точек входа/выхода) →
форсированно перезагружает кэш `finresLoadRealized(true)`, чтобы новая монета тут же появилась в
таблице/показателях, не дожидаясь следующего обновления.

Document-level click-outside-closes-dropdown listener подключается один раз за всё время жизни
страницы (`coinSearchDocListenerWired`), а не при каждом заходе на вкладку — иначе он копился бы.

## Проверка

- `node --check` + баланс скобок CSS (601/601) — без ошибок.
- Юнит-тесты (Node, вне браузера) на скопированной логике: сортировка поиска (точное совпадение с
  начала строки выше подстрочного, `BTC/USDC` корректно исключается как не-USDT-пара), объединение
  `knownSymbols` с текущим балансом (монета, которой уже нет в балансе, но которая была
  "замечена" раньше, попадает в итоговый список символов для запроса) — все проверки прошли.
- Headless Chromium: поле поиска рендерится, ввод показывает корректное «ничего не найдено» (честно
  — в этой песочнице coinMap пуст, WS с protobuf заблокирован), дропдаун закрывается по клику снаружи,
  многократные заходы на вкладку «Сделки» не ломают поиск повторно. Ноль ошибок в консоли/на странице
  на всех вкладках.
- Оговорка та же, что в раунде 10: реальные результаты поиска и заполненную таблицу с данными
  проверить вживую в этой песочнице нельзя (protobufjs с CDN заблокирован → `coinMap` пуст), поэтому
  логика matching/sort и union протестирована юнит-тестами на синтетических данных, а UI —
  на корректности пустых состояний и отсутствии крашей.

## Пересборка .exe

«Скачать приложение», guard `Neutralino.init()`, вырезание `desktopAppData`-блоба) → `node --check`
→ `neu build --release --embed-resources` → `strings` подтвердил присутствие нового кода
(`wireFinresCoinSearch`, `buildCoinSearchResultsHtml`, `rememberSymbol`, `KNOWN_SYMBOLS_KEY`) →

## Итог раунда

Список монет в журнале сделок стал по-настоящему полным: чипы текущего баланса + поиск по всему
