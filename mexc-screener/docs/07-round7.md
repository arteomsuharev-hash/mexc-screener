# MEXC Screener — фидбек по раунду 6: без мигания, TV-тулбар, календарь P&L, журнал сделок (раунд 7)

Продолжение `06-round6.md`. Юзер прислал 2 скриншота (свой график, блок баланса) и попросил: (1) убрать
вспыхивание цвета цены в таблице; (2) переработать управление/кнопки/дизайн "своего графика" под аналог
TradingView; (3) дашборд баланса — календарь P&L по дням, список монет с заработком/убытком покрасивее,
и журнал сделок (список торгованных монет → график с точками входа/выхода).

## 1. Убрано мигание цены в таблице

Откатили тикер-флеш ячейки цены (`cell-flash-up`/`cell-flash-down`, `prevRowSnapshot`) из раунда 6 —
юзеру не понравилось. Остальные анимации раунда 6 (появление строк на первой отрисовке, свечение
сигнальных бейджей, пульс метрик топ-бара) оставлены как есть — жалоба была именно про мигание цены.

## 2. "Свой график" — тулбар в стиле TradingView

Раньше все кнопки (тип графика, MA, инструменты рисования, очистка, сброс) были в одну горизонтальную
строку — тесно и не похоже на TradingView. Переструктурировано под настоящую TV-раскладку:

- **`.own-chart-topbar`** — верхняя полоса: сегмент-контрол типа графика (свечи/линия/область,
  `.ochart-segmented`, единая "таблетка" с подсветкой активного сегмента), пилюля MA 7/25
  (`.ochart-pill`, с текстовой подписью, не только иконкой), по центру — текущая подсказка инструмента
  (`#ochartHint`), справа — очистка построений и сброс масштаба (`.ochart-topbar-right`).
- **`.ochart-body`** → **`.ochart-vtoolbar`** — вертикальная колонка инструментов рисования слева от
  холста (курсор, уровень, отрезок, луч, прямая, линейка) — именно так организована палитра
  инструментов на TradingView (в отличие от горизонтальной ленты, как было раньше).
- Все кнопки сохранили класс `.ochart-tool` и свои `id`/`data-*` атрибуты — JS-обработчики
  (`querySelectorAll('.ochart-tool[data-tool]')` и т.д.) не пришлось трогать, только HTML-разметку и
  CSS вокруг них.
- Canvas сам не требует правок — читает `clientWidth/clientHeight` при каждой отрисовке, поэтому
  корректно подстроился под новую (более узкую) ширину `.own-chart-canvas-wrap` после появления
  вертикальной колонки слева.

## 3. Дашборд баланса — календарь P&L по дням

- **`buildBalanceStatsGridHtml`/`computeDailyPnlMap`** — новая агрегация той же истории снимков
  баланса (`BALANCE_HISTORY`, те же данные, что уже питают стат-плитки/"заработано по монетам" из
  раунда 6), сгруппированной по календарным дням: для каждого дня — последний снимок дня минус
  последний снимок предыдущего дня с данными.
- **Важная оговорка** (задокументирована и в самом коде, и здесь): это изменение ОБЩЕЙ стоимости
  портфеля за день, а не "чистый" реализованный P&L по сделкам — ввод/вывод средств тоже повлияет на
  цифру. Это тот же принцип, что уже используется во всей остальной статистике баланса приложения —
  единственный технически осуществимый способ построить P&L **всего** портфеля по дням, поскольку
  MEXC не отдаёт единый эндпоинт "все сделки по всем парам сразу" (см. п.4 — там поэтому журнал
  ограничен монетами из текущего баланса).
- **UI**: `.balance-calendar-card` — карточка с навигацией по месяцам (`◀ Август 2026 ▶`), сеткой
  7×N дней (пн-старт недели), каждая ячейка — число + сумма (если есть данные), цвет/интенсивность
  фона зависят от знака и размера изменения (зелёный/красный, `--intensity` через inline CSS custom
  property, как heatmap), сегодняшний день обведён синей рамкой. Снизу — сводка "за месяц: +X$,
  дней с данными: N".
- Выбранный месяц (`balanceCalendarMonth`) хранится в module-level переменной и переживает
  авто-обновление баланса (раз в 3с) — при каждом рендере `renderBalanceCalendar()` просто
  перерисовывает данные в уже выбранном месяце, не сбрасывая навигацию юзера обратно на текущий.

## 4. Блок "заработано по монетам" — редизайн

Было: мелкие инлайн-пилюли текстом без иконок/аватаров. Стало: `.balance-earn-card` — карточки в
том же визуальном языке, что и список активов (`.balance-asset-row`): аватар монеты (первые 3 буквы
на цветном круге, тот же `getCoinColor`), "было → стало" в USDT, справа — сумма с иконкой ↑/↓ и
процентом изменения (если известна база для расчёта %).

## 5. Журнал сделок — точки входа и выхода на графике

Техническая оговорка: MEXC не даёт единого списка сделок по всем парам сразу — только по конкретному
`symbol` (`/api/v3/myTrades?symbol=X`, подписанный приватный запрос). Поэтому список монет для журнала
строится из **текущего баланса** (то, что уже гарантированно даёт рабочий `symbol` через
`coinMap.get(asset + '/USDT').raw`), а не как полноценная историческая база по всем когда-либо
торгованным (и уже полностью закрытым и выведенным из баланса) позициям — это осознанное ограничение,
не баг. (Устранено расширением списка символов в раунде 11 — `knownSymbols`, память навсегда.)

- **`fetchMyTrades(raw, limit)`** — подписанный GET, тот же fetch()→curl.exe фолбэк-паттерн, что и у
  `mexcSignedRequest` в целом. `isBuyer: true` → зелёная точка входа (BUY), `false` → красная точка
  выхода (SELL).
- **`pickJournalTf(backMs)`** — подбирает таймфрейм свечей так, чтобы диапазон "от самой ранней сделки
  до сейчас" уложился в ≤900 свечей (лимит API — 1000) — иначе старая сделка окажется за пределами
  загруженного графика. Эскалация 5м → 15м → 1ч → 4ч → 1д.
- **`drawJournalChart(canvas, candles, trades)`** — отдельный (не переиспользующий стейт основного
  "своего графика", чтобы не пересекаться с его зумом/инструментами рисования) статический
  канделстик-рендер: свечи в палитре `#26A69A`/`#EF5350` (та же, что у "своего графика") + треугольные
  маркеры сделок (зелёный ▲ снизу свечи — вход, красный ▼ сверху — выход) в точке свечи, на которую
  попадает время сделки.
- **UI**: список монет-чипов `.journal-chip` внизу блока баланса (аватар + тикер) → клик открывает
  модалку `#journalModal` (920×78vh, левая часть — график, правая — прокручиваемый список сделок с
  временем/ценой/объёмом, цвет по стороне).
- Делегирование клика по чипам повешено ОДИН раз на `#accountBalances` (сам контейнер не пересоздаётся
  при каждом 3-секундном авто-обновлении, только его `innerHTML`) — не плодит дублирующихся
  обработчиков. (В раунде 8 журнал переехал на страницу «Финрез» → «Сделки», делегирование там — на
  `#finresContent`.)
- Ресайз окна, пока модалка открыта, перерисовывает `journalChartState` (добавлено в общий debounced
  `window.resize`-обработчик рядом с балансовыми/канделстик графиками).
