# Автообновление desktop-приложения

Кнопка «Проверить обновления» (страница «Настройки» → «Обновления») сверяется с последним
GitHub Release указанного репозитория и, если найдена более новая версия, может сама скачать
`.zip`-архив релиза, распаковать его и подменить запущенный `MEXC-Screener.exe`.

## Что нужно сделать один раз, чтобы это заработало

1. Создать GitHub-репозиторий (публичный — приватный потребует токен авторизации, которого у
   обычных пользователей приложения нет; неавторизованный GitHub API даёт достаточно запросов в час
   для проверки обновлений).
2. Подключить его как `origin`: `git remote add origin https://github.com/<владелец>/<репозиторий>.git`.
3. Открыть `web/js/app.js`, найти константы `UPDATE_REPO_OWNER`/`UPDATE_REPO_NAME` (в самом начале
   файла) и вписать реальные значения вместо `YOUR_GITHUB_USERNAME`/`YOUR_REPO_NAME`.
4. При каждом релизе:
   - поднять `"version"` в `desktop/neutralino.config.json`;
   - собрать `desktop/build.sh` (или `--embed`, если нужно ещё и обновить кнопку «Скачать
     приложение» на сайте) — на выходе получится `MEXC-Screener-Windows.zip`;
   - опубликовать релиз с тегом вида `v1.1.0` (можно с `v`, можно без — сравнение версий его
     игнорирует) и прикреплённым `MEXC-Screener-Windows.zip`:
     ```bash
     gh release create v1.1.0 MEXC-Screener-Windows.zip --title "v1.1.0" --notes "Что изменилось"
     ```
     (без `gh` — то же самое вручную через веб-интерфейс GitHub: Releases → Draft a new release).

Отдельно ничего специально паковать для автообновления не нужно — используется тот же zip, что и
для ручного скачивания.

## Как это работает технически

- «Проверить обновления»: `GET https://api.github.com/repos/<owner>/<repo>/releases/latest`
  (без токена), сравнение `tag_name` с текущей версией приложения (`APP_VERSION` в `app.js`, для
  desktop-сборки берётся из `window.NL_APPVERSION`, который сама Neutralino подставляет в
  страницу).
- «Скачать и установить» (доступно только в desktop-приложении):
  1. `curl.exe` скачивает `.zip`-ассет релиза прямо на диск, в папку с работающим `.exe`.
  2. `powershell -Command Expand-Archive` распаковывает его во временную подпапку.
  3. Генерируется маленький bat-помощник, который: ждёт освобождения файла `MEXC-Screener.exe`
     (переименование запущенного `.exe` — штатно разрешённая на Windows операция, но требует, чтобы
     процесс уже закрылся), делает резервную копию `MEXC-Screener.exe.bak`, ставит новую версию на
     место, перезапускает приложение и подчищает за собой временные файлы.
  4. Приложение вызывает `Neutralino.app.exit()`, помощник (уже отвязанный процесс) доделывает
     подмену и запускает новый `.exe`.

При любой ошибке на шагах 1–3 старый `.exe` не трогается — пользователь ничего не теряет.
`.bak`-копия остаётся рядом даже при успешной установке, на случай если новая версия окажется
неработоспособной — её можно вручную переименовать обратно.

## Важно перед тем, как раздавать обновление другим людям

Подмена запущенного `.exe` — единственная часть механизма, которую нельзя протестировать в
песочнице разработки (там нет реального Windows-процесса, который можно понаблюдать вживую).
Приём стандартный (rename-then-replace, используется многими небольшими Windows-приложениями), но
**прогоните полный цикл (проверка → скачивание → установка → перезапуск) сами хотя бы один раз на
реальной машине**, прежде чем полагаться на него для пользователей, которые не смогут
самостоятельно разобраться в проблеме, если что-то пойдёт не так.
